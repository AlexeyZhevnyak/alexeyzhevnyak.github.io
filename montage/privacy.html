Privacy Policy

montage · last updated 22 September 2026

montage is a command-line tool that runs on its operator's own computer. It has no server, no accounts and no other users. This policy describes what it does with Google user data, which in practice means the operator's own YouTube account.

What data is accessed

montage asks for one OAuth 2.0 scope and no others:

  • https://www.googleapis.com/auth/youtube.upload

That scope permits uploading videos to the authorising account's channel. It does not grant access to watch history, subscriptions, comments, analytics, playlists, personal profile information, or any other Google service.

montage sends no read requests to any Google API. It does not list, search, download or analyse content or account information, and it holds no permission that would allow it to.

What the data is used for

The access token is used for exactly two operations, both of which publish files the operator produced on their own machine:

EndpointPurpose
videos.insertUpload a rendered video file to the operator's channel.
thumbnails.setAttach the cover image rendered alongside that video.

Uploads are made privately by default. The operator decides the visibility of every video. No other use is made of the authorisation, and montage will not use it for a purpose not described here.

What is stored, and where

Everything montage stores lives on the operator's own computer. Nothing is stored on a server, because there is no server.

ItemLocationPermissions
OAuth refresh and access tokens ~/.config/montage-helper/credentials/ files 0600, directory 0700
Publishing queue: which file goes to which channel, when, and the resulting video id ~/.local/state/montage-helper/queue.json 0600
Video and image files the operator's own project directories as created by the operator

What is shared

Nothing, with anyone. montage transmits data to exactly one destination — the YouTube Data API, to upload the operator's own videos to the operator's own channel. It contacts no analytics service, no advertising network, no error-reporting service and no third-party backend. No data is sold, rented, or disclosed to any other party.

Other parts of montage that are unrelated to Google — rendering, music generation and speech alignment — also run entirely on the operator's machine. Audio and video are never uploaded to a transcription or generation service.

Retention and revocation

Tokens are kept until the operator removes them or Google invalidates them. The operator can revoke montage's access at any time in two independent ways:

  • delete the credential files under ~/.config/montage-helper/credentials/, which removes the stored tokens immediately;
  • revoke the grant at myaccount.google.com/permissions, which invalidates it at Google's end.

Because montage keeps no server-side copy, deleting the local files is a complete deletion.

Compliance

montage's use of information received from Google APIs adheres to the Google API Services User Data Policy, including its Limited Use requirements. Use of the YouTube Data API is subject to the YouTube API Services Terms of Service and the Google Privacy Policy.

Changes

If montage's use of Google user data changes, this policy will be updated before the change takes effect, and the date at the top of this page will be revised.
